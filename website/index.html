§1

What Parvaz does

Mission brief

Parvaz is an Android app that helps you open websites your network blocks. You need an access link from someone you trust. It starts with parvaz://. That person, your helper, sets up a relay: a small program on a Google account that fetches websites for you. Parvaz sends your browser's traffic to the relay.

Your helper sends you the link through Signal or a Telegram Secret Chat, not WhatsApp. You install the app, tap or paste the link, install a certificate in Android Settings (once), tap the PARVAZ button, and browse in Chrome. Parvaz opens in Persian. You can switch to English or Danish in its settings.

Parvaz needs Android 11 or later and a 64-bit ARM phone. It installs on Android 7 to 10 but cannot connect there. It is early software (pre-alpha). It follows the design of MasterHttpRelayVPN-RUST and adds an app that is Persian by default, with guided steps for the access link and the certificate.

What the app does and does not do

What the app won't do · what it must do · the limits
Won't do No
  • No analytics, telemetry or remote logs (yet).
  • No relay run by Cocode. You use your own relay, or one run by a helper you trust.
  • No access to your location, contacts, SMS, microphone or camera. Parvaz does not ask for camera permission.
  • No update checks, no ads, no crash reporting.
  • No servers run by Cocode, no accounts, no sign-in.
You can check this: the permissions are listed in AndroidManifest.xml in the source code.
Must do Yes
  • VpnService: lets Parvaz receive your phone's internet traffic. Android asks you once.
  • INTERNET + FOREGROUND_SERVICE: reach Google and keep running in the background.
  • POST_NOTIFICATIONS (Android 13 and later): show the notice that Parvaz is connected.
  • A screen lock on the phone. Android will not install a certificate without one.
  • A Chromium browser: Chrome, or Brave, Edge or Vivaldi. No browser flags needed.
QR scanning is not available in this version.

§6

What works, what does not

Who flies, who's grounded
Heads-up Not every site opens, and WebSockets are not supported in this version.
Works Tunnels
  • Chrome on Android: no flags, no about:config, no root.
  • Other Chromium browsers (Brave, Edge, Vivaldi) should work the same way. Other browsers vary.
  • Web apps inside Chrome, such as Gmail, GitHub, Wikipedia, news sites and search.
  • Google sites (google.com, youtube.com) use the relay too in this version, so they count against its daily limit.
Speed is about 5 KB/s, so pages load slowly. WebSockets do not work yet.
Does not work Won't tunnel
  • Android 10 and older. The app installs, but it cannot connect. It needs Android 11 or later.
  • Firefox is not tested with Parvaz. It keeps its own certificate list, and has a Use third party CA certificates option in its Secret Settings that Parvaz has not been checked with (Mozilla bug 1894053).
  • DuckDuckGo browser. It is Chromium-based but rejects the certificate. Confirmed not working.
  • Apps such as Instagram, Telegram, WhatsApp, banking and streaming apps. Since Android 7, apps do not accept certificates you install.
This is how Android works, so Parvaz cannot change it. For other apps you need a different tool, for example xray on your own server.

§8

Install the certificate · in Settings

Step 1 of 2 · once · ~30 seconds

A certificate is a small file that tells your phone to trust Parvaz for your browser's secure connections. In Parvaz, tap Open Settings. Parvaz saves a certificate file and opens Android Settings. If you cannot find the file, tap Show file. Then follow the path for your phone.

proc · cert.001 · samsungOne UI 6 / Android 14
# SAMSUNG (Galaxy): Settings → Security and privacy → More security settings → Install from device storage → CA certificate → choose the newest parvaz-ca-…crt file (name starts with parvaz-ca-, ends with .crt) → enter your PIN / fingerprint → tap Install anyway on the warning
proc · cert.001 · pixel / aospAndroid 14 / 15
# PIXEL / stock Android: Settings → Security & privacy → More security & privacy → Encryption & credentials → Install a certificate → CA certificate → choose the newest parvaz-ca-…crt file (name starts with parvaz-ca-, ends with .crt) → enter your PIN / fingerprint → tap Install anyway on the warning

You need a screen lock (PIN, pattern or password), or Android will not install the certificate. Can't find the menu? Search for CA certificate in Settings. Android shows a warning. That is expected: Parvaz made this certificate on your phone, and its private key stays in the app's private storage. Tap Install anyway.

§9

Tap PARVAZ · open Chrome

Step 2 of 2 · once · ~10 seconds

Tap the PARVAZ button on Parvaz's main screen (پرواز in Persian). When it changes to IN FLIGHT (در پرواز), open Chrome and browse as usual. HTTPS pages go through Parvaz with no further setup. To disconnect, tap the button again. Brave, Edge and Vivaldi should work the same way.

proc · browser.001 · chromiumone-time · ~10 sec
# 1. In Parvaz, tap the PARVAZ button. → the outlined "PARVAZ" button turns into a filled "IN FLIGHT" button # 2. Open Chrome (or Brave / Edge / Vivaldi). → just browse · no flags, no about:config, no root # 3. (Optional) check that it works: open wikipedia.org # goes through the relay open google.com # also goes through the relay

Why Chrome works: Chrome on Android trusts certificates you install in Android Settings, and its Certificate Transparency checks have an explicit exception for certificates that chain to one of them. So Chrome accepts the certificates Parvaz makes, with no setup. Browsers that do not work, and the speed and WebSocket limits, are in §6.

Helper · deploy the relay

~5 min · once · technical helper only

If you are the technical helper setting Parvaz up for someone else, here is the one-time Apps Script deployment. The person you help never opens script.google.com.

proc · relay.deploy.001script.google.com · ~5 min
# 1. Open Apps Script and create a new project open script.google.com # click "New project" # 2. Paste the relay code into Code.gs (replace the default contents) view github.com/cocodedk/parvaz/blob/main/apps_script/Code.gs copy → paste into the Code.gs tab in the editor # 3. Generate a strong random AUTH_KEY (do not reuse passwords) openssl rand -base64 32 # or any password manager · 32+ chars → in Code.gs, set: var AUTH_KEY = "<paste-here>"; → File → Save (Ctrl/Cmd+S) # 4. Deploy as a Web App Deploy → New deployment → ⚙ Web app Execute as: Me (your-email@gmail.com) Who has access: Anyone → click Deploy → Google asks for OAuth consent the first time → Allow # 5. Find the URL that goes into the Parvaz app Apps Script gives you a Web app URL that looks like: https://script.google.com/macros/s/AKfycbyLONGRANDOMTOKEN/exec └────────────┬────────────┘ deployment-id # the only piece you need You can re-open it any time: Deploy → Manage deployments → copy the Web app URL # 6. Build the parvaz:// access link by combining the two pieces above parvaz://<deployment-id>/<AUTH_KEY>#<display-name> # concrete example: parvaz://AKfycbyLONGRANDOMTOKEN/7dF9KmY...eY=#رلهٔ‌من # 7. Share it through a secure messenger only: this link contains the key ✓ Signal · end-to-end encrypted · recommended ✓ Telegram Secret Chat · end-to-end encrypted ✗ Telegram regular chat · not end-to-end encrypted → NEVER ✗ WhatsApp · chat backups can be readable unless encrypted backups are on → avoid ✗ SMS · carrier-readable → NEVER ✗ Email · server-readable → NEVER

Limits: a free Google account gets 20,000 URL fetches a day, shared by all its scripts. One script run lasts at most 6 minutes. Parvaz waits up to 30 seconds for the relay's reply. Use an account you control and follow Google's terms. Test it: open the Web app URL in a browser. You should see a page that says "Welcome" and "This application is running normally." That shows the deployment is live. It does not test your AUTH_KEY. Source: apps_script/Code.gs · Apps Script · Web Apps.
